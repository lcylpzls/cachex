# cachex 架构决策记录(ADR)

> 状态说明:**已接受**。D1–D7 已于 2026-08-09 全部按推荐确认。

## ADR-001:分片锁 + 精确 LRU

- **状态**:建议(基础决策)
- **决策**:默认 16 个 shard,FNV-1a 哈希分桶;
  每 shard `map + container/list` 实现精确 LRU;
- **影响**:命中路径需写锁更新顺序,分片把竞争摊薄 16 倍。

## ADR-002:TTL 双通道过期,后台清理默认开启

- **状态**:建议(对应 D3 / D4)
- **决策**:每条目独立 TTL(默认不过期);
  惰性过期 + 后台定期清理(默认间隔 1 分钟,可关闭);
- **影响**:过期条目不会长期滞留,低频清理成本可忽略。

## ADR-003:Singleflight 合并回源,包级 GetOrSet

- **状态**:建议(对应 D1)
- **决策**:`GetOrSet(ctx, c, key, ttl, loader)` 为包级函数,
  未命中按 key 合并;loader 失败不缓存、错误透传;
- **影响**:Cache 方法集保持最小,回源语义独立可扩展。

## ADR-004:值类型保持 any,零拷贝

- **状态**:建议(对应 D5)
- **决策**:value 为 `any`,不做 []byte 特化;
- **影响**:业务零序列化开销,GC 压力由分片与容量控制兜底。

## ADR-005:总条目容量 + 逐出回调带原因

- **状态**:建议(对应 D2 / D6)
- **决策**:`WithCapacity` 总条目上限(默认 10000,0 不限);
  `WithOnEvicted` 回调区分容量逐出与过期清理;
- **影响**:容量语义对调用方直观,逐出可联动外部失效。

## ADR-006:观测默认 no-op,错误统一 errx

- **状态**:建议
- **决策**:Metrics 外部注入(默认 no-op),Stats 原子计数;
  配置校验错误统一 `CACHEX_INVALID_CONFIG`;
- **影响**:与 dbx / httpx 观测形态一致,热路径仅原子计数。

## ADR-007:Close / Cleanup 幂等安全

- **状态**:建议
- **决策**:`Close()` 可重复调用,停止后台任务后置标记;
  `Cleanup()` 并发安全;
- **影响**:生命周期管理简单,不引入错误返回噪音。

## ADR-008:逐出回调在锁外调用

- **状态**:建议
- **决策**:容量逐出与过期清理先收集 (key, value, reason),
  释放 shard 锁后再调用 `OnEvicted`;
- **影响**:回调可安全反查或写入 cache,不会死锁。

## ADR-009:Metrics 与生态同形态,loader 耗时可观测

- **状态**:建议(对应 D7)
- **决策**:Metrics 接口与 dbx / httpx 一致
  (`IncCounter` + `ObserveDuration`);
  `GetOrSet` 记录 loader 耗时观测;
- **影响**:指标生态统一,回源慢可被监控发现。
