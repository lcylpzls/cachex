# cachex 与竞品全维度对比

> 更新日期:2026-08-09 · cachex v0.2.0
> 性能数据:同机(Windows / AMD Ryzen 5 7600),对比工程 `.bench-compare/`(本地,未入库)

## 1. 性能

### Get 命中(先写入后读取,单 goroutine)

| 实现 | ns/op | B/op | allocs/op |
| --- | --- | --- | --- |
| go-cache | 7.1 | 0 | 0 |
| 手写 16 分片 map(基线) | 12.0 | 0 | 0 |
| **cachex(精确 LRU)** | **18.7** | **0** | **0** |
| ristretto | 31.1 | 7 | 0 |
| bigcache | 37.7 | 14 | 1 |
| freecache | 43.7 | 1 | 1 |

### Set(写入固定键)

| 实现 | ns/op | B/op | allocs/op |
| --- | --- | --- | --- |
| 手写 16 分片 map(基线) | 24.1 | 7 | 0 |
| go-cache | 24.6 | 7 | 0 |
| **cachex** | **28.2** | **7** | **0** |
| freecache | 44.8 | 7 | 0 |
| bigcache | 87.5 | 127 | 1 |
| ristretto | 187.9 | 88 | 2 |

### 容量逐出(cachex 专有基准)

| 实现 | ns/op | B/op | allocs/op |
| --- | --- | --- | --- |
| **cachex v0.2.0** | **232.5** | 164 | 4 |

### 解读

- go-cache 的 Get 快是因为全局 RWMutex 读锁 + **无 LRU 刷新、无容量控制**,
  本质是「带 TTL 的并发 map」;
- cachex 的 Get 在 0 分配下额外完成了:精确 LRU 顺序维护、全局单调序号、
  原子统计;Set 快于全部字节型竞品;
- bigcache/freecache 的 Set 慢在字节拷贝与环形缓冲管理;
- ristretto 的 Set 慢在异步事务缓冲 + 频率估计器更新。

## 5. 选型建议

- **业务对象缓存 / 会话 / 热点数据**(需要失效、容量、击穿防护):**cachex**;
- 极简「带 TTL 的 map」:go-cache(注意已基本停更);
- 高吞吐二进制流(日志、事件缓冲,可接受序列化):bigcache;
- 超大容量内存敏感(几十 GB 级,可接受预分配):freecache;
- 复杂工作负载追求极限命中率(可接受调参与异步):ristretto。

## 6. cachex 的独特定位

同时具备「any 零拷贝 + 严格容量 + 精确/采样 LRU + Singleflight 击穿防护 +
锁外逐出回调 + 全量统计 + 零第三方」的组合,在竞品中无直接等价物;
与 go-cache 相比多了 LRU/容量/统计/击穿,与 ristretto 相比多了 TTL/严格容量/
同步可见,与 bigcache/freecache 相比多了类型便利与治理能力。
